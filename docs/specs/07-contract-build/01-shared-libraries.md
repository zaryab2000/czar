## 6. `CzarConstants.sol`

### 6.1 What it is
- File-level constants, with no `library` wrapper. Any file imports exactly the names it uses:
  - `import {BPS, MAX_AUTHORIZATIONS_PER_RESERVATION} from "../libraries/CzarConstants.sol";`
- The values come from `czar-vault.md` §3 and the vectors file. Types are binding.
- Five names are not in `czar-vault.md` §3 yet, although the spec uses their values. The spec-fix PR adds them to §3:
  - `FORCE_CLOSE_DELAY`: the "expiresAt + 1 day" in §5.2.
  - `CANCEL_REASON`: `keccak256("czar:cancel")`, from `job-escrow-adapter.md` §3.
  - `DESCRIPTION_PREFIX`: the `"czar:"` prefix, from JOB-3.
  - `CZAR_ESCROW_EVALUATION_GRACE`: the 1 h grace in §5.5 `claimJobRefund`.
  - `REQUIRE_UV`: §7.
- They live here so no other file holds a literal.

## 7. Library files

### 7.1 `SatMath.sol`
- `sat(a, b)` returns `a − b`, or 0 when `b ≥ a`. Use it only where a PRD says "saturating" (00-conventions §4.8).
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.30;

library SatMath {
    /// @dev a − b, or 0 when b ≥ a (czar-vault.md §4 "sat"; RV-008, RV-011).
    function sat(uint256 a, uint256 b) internal pure returns (uint256) {
        return a > b ? a - b : 0;
    }
}
```

### 7.2 `CzarHashing.sol`
- **What it does:** every EIP-712 domain separator, struct hash and digest the vault computes, plus the Gateway replay hash.
- **Field order is binding** in every function. It matches 02 §6.2 and the vendor sources.
- **`TransferSpecFields`** is a file-level struct holding the 13 Gateway `TransferSpec` fields. `hookData` is left out because it is always empty in Czar; the struct hash uses `keccak256("")` and the byte encoding uses length 0.
- **Two different hashes of the same fields** (both are needed):
  - `transferSpecStructHash` is the EIP-712 struct hash, made of 32-byte words. It goes inside the `BurnIntent` digest.
  - `transferSpecReplayHash` is the keccak of the 340-byte packed encoding. It is the Gateway replay id that `GatewayMinter.isTransferSpecHashUsed` takes (czar-vault.md §5.4).
- **Why some functions use two `abi.encode` or `bytes.concat` calls:** one call with 14 or 15 values hits "stack too deep" without `via_ir`. Every value is a static 32-byte word or fixed bytes, so the concatenation gives the same bytes as one call. The vector tests prove it. Do not merge the calls.
- **The domain functions take the chain id and contract as arguments.** The vault computes its three separators once, in its constructor (PRD 04).
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.30;

import {MessageHashUtils} from "@openzeppelin/contracts/utils/cryptography/MessageHashUtils.sol";
import {ICzarVault} from "../interfaces/ICzarVault.sol";
import {
    EIP712_DOMAIN_FULL_TYPEHASH,
    EIP712_DOMAIN_NO_CONTRACT_TYPEHASH,
    TRANSFER_WITH_AUTHORIZATION_TYPEHASH,
    TRANSFER_SPEC_TYPEHASH,
    BURN_INTENT_TYPEHASH,
    RECEIPT_TYPEHASH,
    RECEIPT_ATTESTATION_TYPEHASH,
    AUTONOMY_RAISE_TYPEHASH,
    OWNER_ACTION_TYPEHASH,
    TRANSFER_SPEC_MAGIC
} from "./CzarConstants.sol";

library CzarHashing {
    /// @dev EIP-712 domain with chainId and verifyingContract (02 §6.1: USDC, CzarVault).
    function domainSeparatorFull(bytes32 nameHash, bytes32 versionHash, uint256 chainId, address verifyingContract)
        internal pure returns (bytes32)
    {
        return keccak256(abi.encode(EIP712_DOMAIN_FULL_TYPEHASH, nameHash, versionHash, chainId, verifyingContract));
    }

    /// @dev EIP-712 domain with chainId and no contract (02 §6.1: SelectionLayer).
    function domainSeparatorNoContract(bytes32 nameHash, bytes32 versionHash, uint256 chainId)
        internal pure returns (bytes32)
    {
        return keccak256(abi.encode(EIP712_DOMAIN_NO_CONTRACT_TYPEHASH, nameHash, versionHash, chainId));
    }

    /// @dev "\x19\x01" ‖ domain ‖ structHash, via OpenZeppelin (02 §6.1 last line).
    function typedDataHash(bytes32 domainSeparator, bytes32 structHash) internal pure returns (bytes32) {
        return MessageHashUtils.toTypedDataHash(domainSeparator, structHash);
    }

    /// @dev USDC TransferWithAuthorization struct hash (02 §6.3.1).
    function transferWithAuthorizationHash(
        address from, address to, uint256 value, uint256 validAfter, uint256 validBefore, bytes32 nonce
    ) internal pure returns (bytes32) {
        return keccak256(abi.encode(TRANSFER_WITH_AUTHORIZATION_TYPEHASH, from, to, value, validAfter, validBefore, nonce));
    }

    /// @dev Gateway TransferSpec struct hash (czar-vault.md §6.2 table; hookData is empty, so its hash is keccak256("")).
    /// Field order is binding: version, sourceDomain, destinationDomain, sourceContract, destinationContract,
    /// sourceToken, destinationToken, sourceDepositor, destinationRecipient, sourceSigner, destinationCaller, value, salt, hookData.
    function transferSpecStructHash(TransferSpecFields memory f) internal pure returns (bytes32) {
        // Split in two abi.encode calls to stay under the 16-slot stack limit without via-IR.
        // All fields are static 32-byte words, so the concatenation equals one abi.encode of all 15 values.
        return keccak256(bytes.concat(
            abi.encode(TRANSFER_SPEC_TYPEHASH, f.version, f.sourceDomain, f.destinationDomain, f.sourceContract, f.destinationContract, f.sourceToken),
            abi.encode(f.destinationToken, f.sourceDepositor, f.destinationRecipient, f.sourceSigner, f.destinationCaller, f.value, f.salt, keccak256(""))
        ));
    }

    /// @dev Gateway BurnIntent struct hash (czar-vault.md §6.2 step 3).
    function burnIntentStructHash(uint256 maxBlockHeight, uint256 maxFee, bytes32 specStructHash)
        internal pure returns (bytes32)
    {
        return keccak256(abi.encode(BURN_INTENT_TYPEHASH, maxBlockHeight, maxFee, specStructHash));
    }

    /// @dev Gateway replay id: keccak256 of the 340-byte TransferSpec encoding (czar-vault.md §5.4 requestPullback;
    /// TransferSpec.sol lines 50–67). The last field is the hookData length (uint32 0); hookData itself is empty.
    function transferSpecReplayHash(TransferSpecFields memory f) internal pure returns (bytes32) {
        // Two nested concats (stack limit without via-IR). Byte layout: 4 + 3×4 + 8×32 + 32 + 32 + 4 = 340.
        bytes memory head = bytes.concat(
            TRANSFER_SPEC_MAGIC, bytes4(f.version), bytes4(f.sourceDomain), bytes4(f.destinationDomain),
            f.sourceContract, f.destinationContract, f.sourceToken, f.destinationToken
        );
        bytes memory tail = bytes.concat(
            f.sourceDepositor, f.destinationRecipient, f.sourceSigner, f.destinationCaller,
            bytes32(f.value), f.salt, bytes4(uint32(0))
        );
        return keccak256(bytes.concat(head, tail));
    }

    /// @dev SL Receipt struct hash (02 §6.3.3); `originAsserted` is hashed as keccak256(bytes(string)).
    function receiptStructHash(ICzarVault.SlReceipt memory r) internal pure returns (bytes32) {
        // Split in two abi.encode calls (stack limit without via-IR); every field is a static 32-byte word.
        return keccak256(bytes.concat(
            abi.encode(RECEIPT_TYPEHASH, r.paymentRefHash, r.requestCommit, r.responseCommit, r.statusCode, keccak256(bytes(r.originAsserted)), r.requirementsHashSeen),
            abi.encode(r.tRequest, r.tPaymentSigned, r.tComplete, r.outcome, r.localChecksCommit, r.disclosure, r.createdAt)
        ));
    }

    /// @dev ReceiptAttestation(bytes32 receiptStructHash) struct hash (02 §6.2; RV-013).
    function receiptAttestationStructHash(bytes32 receiptHash) internal pure returns (bytes32) {
        return keccak256(abi.encode(RECEIPT_ATTESTATION_TYPEHASH, receiptHash));
    }

    /// @dev AutonomyRaise(bytes32 category,uint256 newLimit,uint64 periodId,uint256 nonce,uint256 deadline).
    function autonomyRaiseStructHash(bytes32 category, uint256 newLimit, uint64 periodId, uint256 nonce, uint256 deadline)
        internal pure returns (bytes32)
    {
        return keccak256(abi.encode(AUTONOMY_RAISE_TYPEHASH, category, newLimit, periodId, nonce, deadline));
    }

    /// @dev OwnerAction(uint8 action,bytes32 payloadHash,uint256 nonce,uint256 deadline).
    function ownerActionStructHash(uint8 action, bytes32 payloadHash, uint256 nonce, uint256 deadline)
        internal pure returns (bytes32)
    {
        return keccak256(abi.encode(OWNER_ACTION_TYPEHASH, action, payloadHash, nonce, deadline));
    }

    /// @dev Left-pads an address to bytes32 (Gateway uses bytes32 addresses).
    function toBytes32(address a) internal pure returns (bytes32) {
        return bytes32(uint256(uint160(a)));
    }
}

/// @dev The 14 TransferSpec fields (hookData omitted: always empty in Czar).
struct TransferSpecFields {
    uint32 version;
    uint32 sourceDomain;
    uint32 destinationDomain;
    bytes32 sourceContract;
    bytes32 destinationContract;
    bytes32 sourceToken;
    bytes32 destinationToken;
    bytes32 sourceDepositor;
    bytes32 destinationRecipient;
    bytes32 sourceSigner;
    bytes32 destinationCaller;
    uint256 value;
    bytes32 salt;
}
```

### 7.3 `PayeeLeaf.sol`
- **Leaf** = `keccak256(bytes.concat(keccak256(abi.encode(PAYEE_LEAF_TAG, payee, kind, stepIndex, stepCap))))`. The leaf is hashed twice, as in 02 §5.3.
- **Node hashing:** OpenZeppelin `MerkleProof` hashes sorted pairs, which matches the 02 §5.3 node rule.
- **`verify` takes the proof as `calldata`.** The vault receives proofs as `calldata`, and `verifyCalldata` avoids a copy.
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.30;

import {MerkleProof} from "@openzeppelin/contracts/utils/cryptography/MerkleProof.sol";
import {PAYEE_LEAF_TAG} from "./CzarConstants.sol";

library PayeeLeaf {
    /// @dev Double-hashed leaf (02 §5.3): keccak256(bytes.concat(keccak256(abi.encode(TAG, payee, kind, stepIndex, stepCap)))).
    function hash(address payee, uint8 kind, uint32 stepIndex, uint256 stepCap) internal pure returns (bytes32) {
        return keccak256(bytes.concat(keccak256(abi.encode(PAYEE_LEAF_TAG, payee, kind, stepIndex, stepCap))));
    }

    /// @dev True when the leaf is in the tree with this root (sorted-pair nodes, OpenZeppelin MerkleProof).
    function verify(bytes32[] calldata proof, bytes32 root, address payee, uint8 kind, uint32 stepIndex, uint256 stepCap)
        internal pure returns (bool)
    {
        return MerkleProof.verifyCalldata(proof, root, hash(payee, kind, stepIndex, stepCap));
    }
}
```

### 7.4 `CzarNonces.sol`
- **`derivedNonce`** is the EIP-3009 nonce for one authorization index (02 §7.2).
- **`pullbackSalt`** is the burn-intent salt (02 §7.3).
- Both start from `NONCE_TAG` and the vault address. The salt has no `index` word, so a salt can never equal a nonce.
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.30;

import {NONCE_TAG} from "./CzarConstants.sol";

library CzarNonces {
    /// @dev EIP-3009 nonce for index `index` of reservation `reservationId` (02 §7.2).
    function derivedNonce(address vault, uint64 reservationId, uint32 index) internal pure returns (bytes32) {
        return keccak256(abi.encode(NONCE_TAG, vault, reservationId, index));
    }

    /// @dev Burn-intent salt for pullback `pullbackId` (02 §7.3; czar-vault.md §5.4 requestPullback).
    function pullbackSalt(address vault, uint64 pullbackId) internal pure returns (bytes32) {
        return keccak256(abi.encode(NONCE_TAG, vault, pullbackId));
    }
}
```

### 7.5 `PasskeyVerifier.sol`
- **Why a wrapper is needed:**
  - `ICzarVault.WebAuthnAuth` orders its fields `challengeIndex, typeIndex, r, s, authenticatorData, clientDataJSON`.
  - OpenZeppelin's `WebAuthn.WebAuthnAuth` (v5.7.0, `WebAuthn.sol` line 46) orders them `r, s, challengeIndex, typeIndex, authenticatorData, clientDataJSON`.
  - They are different Solidity types, so the vault cannot pass one as the other, and must never `abi.decode` one as the other. The wrapper copies the fields by name.
- **It adds Czar's RP ID check** (czar-vault.md §7): the first 32 bytes of `authenticatorData` must equal the stored `rpIdHash`. OpenZeppelin leaves that check out on purpose.
- **It never reverts on a bad assertion**; it returns `false`. The caller turns `false` into its own error (PRD 10).
- **Facts it relies on:**
  - Arc has the P-256 precompile at `0x…0100`, priced at 6,900 gas (ground truth A6-01, A6-02).
  - OpenZeppelin `P256.verify` calls the precompile and falls back to a Solidity verifier when it is absent. It rejects a high `s` (RV-034).
  - The WebAuthn challenge is the raw 32-byte digest. The browser base64url-encodes it inside `clientDataJSON`.
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.30;

import {WebAuthn} from "@openzeppelin/contracts/utils/cryptography/WebAuthn.sol";
import {ICzarVault} from "../interfaces/ICzarVault.sol";
import {REQUIRE_UV} from "./CzarConstants.sol";

library PasskeyVerifier {
    /// @dev True only if (1) authenticatorData is at least 37 bytes, (2) its first 32 bytes equal rpIdHash,
    /// (3) OpenZeppelin WebAuthn.verify(challenge = abi.encodePacked(digest), auth, qx, qy, REQUIRE_UV) is true.
    /// czar-vault.md §7. Never reverts on a bad assertion; returns false.
    function verify(bytes32 digest, ICzarVault.WebAuthnAuth calldata a, bytes32 qx, bytes32 qy, bytes32 rpIdHash)
        internal view returns (bool)
    {
        if (a.authenticatorData.length < 37) return false;
        if (bytes32(a.authenticatorData[0:32]) != rpIdHash) return false;
        WebAuthn.WebAuthnAuth memory oz = WebAuthn.WebAuthnAuth({
            r: a.r,
            s: a.s,
            challengeIndex: a.challengeIndex,
            typeIndex: a.typeIndex,
            authenticatorData: a.authenticatorData,
            clientDataJSON: a.clientDataJSON
        });
        return WebAuthn.verify(abi.encodePacked(digest), oz, qx, qy, REQUIRE_UV);
    }
}
```

## 9. Test file `contracts/test/unit/Libraries.t.sol`
- **What it covers:** every constant, every hashing function against its vector, both payee trees, the nonce and salt rules, and every passkey case (valid, wrong RP ID, missing UV, high `s`, wrong digest, short authenticator data, gas).
- **Passkey assertions are built inside the test, the way a browser builds them:**

        bytes32 digest = keccak256("digest");
        ICzarVault.WebAuthnAuth memory a = _assertion(digest, RP_ID_HASH, FLAGS_UP_UV);
        uint256 before = gasleft();
        bool ok = this.verifyPasskeyExt(digest, a, qx, qy, RP_ID_HASH);
        uint256 used = before - gasleft();
        assertTrue(ok);
        // 60,000 when the P-256 precompile at 0x100 answers (6,900 gas, A6-02); 300,000 when OpenZeppelin
        // falls back to its Solidity verifier (measured 259,572 on a Prague EVM without the precompile).
        assertLt(used, _precompileMissing() ? 300_000 : 60_000);
    }

    /// @dev True when the P-256 precompile at 0x100 does not verify a valid signature (it returns empty output on
    /// failure, and on chains without it the call also returns empty). OpenZeppelin then uses its Solidity verifier.
    function _precompileMissing() internal view returns (bool) {
        bytes32 h = sha256("probe");
        (bytes32 r, bytes32 s) = vm.signP256(PASSKEY_PK, h);
        (bytes32 qx, bytes32 qy) = _pubKey();
        (bool success, bytes memory ret) = address(0x100).staticcall(abi.encode(h, r, s, qx, qy));
        return !success || ret.length != 32 || uint256(bytes32(ret)) != 1;
    }
