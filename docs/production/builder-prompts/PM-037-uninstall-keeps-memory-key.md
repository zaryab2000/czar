# Builder prompt: PM-037 — Uninstall keeps the memory key when memory is kept

- **Lane:** D (parallel with PM-060)

## Goal

- `czar uninstall` without deleting memory must keep K14, the SQLCipher key. Today it deletes every keychain item (`apps/daemon/src/install.ts`, the `uninstall` loop over `KEYCHAIN_ACCOUNTS`), so kept memory can never be opened again.

## Read first

- `apps/daemon/src/install.ts`, `keychain.ts` (`KEYCHAIN_ACCOUNTS`)
- `apps/daemon/test/install.test.ts`, the case "uninstall removes the agent and the keychain items, and keeps memory unless asked"
- CZ-02 uninstall row in `docs/specs/04-components/local/local-observers-and-daemon.md` (around line 210; read only)

## Scope

- **With `deleteMemory: false`:**
  - delete the device token (K15) and the hook token (K16)
  - keep the memory key (K14) and the support folder
- **With `deleteMemory: true`:** delete all three and the folder, as today.

- Linux (PM-035).

## Tests to write first

- Update the existing uninstall test. **This is a deliberate assertion change: name it in your report.**
  - Keep-memory: K14 is still present, K15 and K16 are gone.
  - Delete-memory: all gone.
- Add a reinstall test: after a keep-memory uninstall and an install, opening the memory database with the stored K14 succeeds. Use the real `better-sqlite3-multiple-ciphers` with a temp folder, as `database.test.ts` does.
